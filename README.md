# DSP32Music —— F28335 硬件 PWM 双声道音乐播放器

基于 **TMS320F28335**（普中 PZ-DSP28335-L 开发板）的硬件 PWM 音频播放器，
双手谱**独立双声道**输出，并带 LCD / 数码管 / 按键 / 灯效交互。

---

## 一、功能特性

| 模块 | 能力 |
|---|---|
| **音频** | ePWM3 单模块驱动**两路独立输出**：GPIO4 = 右手谱、GPIO5 = 左手谱；同一 25 kHz 载波 ⇒ 两手**天然同步**，永不漂移；各自独立循环 |
| **曲表** | 自定义 **6bit 跨字打包**格式，每事件 2 字（4 字节）；**零折叠**、忠实原谱音高；采 6 声道合成 + 包络延音 |
| **增益** | 按声部数归一化（单音与和弦同响度）+ **每声部音高补偿**（同一声部内：最高音 ×1.0 → 低 4 个八度 ×3.0）+ 软限幅 |
| **LED** | 不播放：慢速呼吸/流水；**播放中：跟随音乐最高音**，4 档倍速（×0.5/×1/×1.5/×2） |
| **数码管** | 4 位计数 0..9999；**虚拟时钟**驱动（播放 320 / 停止 6400 虚拟 ms） |
| **LCD1602** | 8 位并口；两行状态显示 + 按键号；**整行重写**（抗 DB1 接触不良）+ **开机 1.5 s 自愈** |
| **按键** | 3×3 矩阵，消抖 + 按下沿检测；K3 = 起停音乐并清零计数，其它键切换灯效 |

```bat

```

## 四、曲表流水线（MIDI/）

**完全自包含、相对路径**（不含任何绝对路径），clone 后可直接重建曲表：

```bash
cd MIDI
python build_tables.py          # 生成 song_tables.h
```

流程：`两个 .mid` → 解析 SMF → 提取音符 → 切分和弦事件 → 6bit 打包 → `song_tables.h`

### 打包格式（2 字 = 4 字节 / 事件）

```
word0 = v0[5:0] | v1[11:6] | v2低位[15:12]
word1 = v2高位[1:0] | v3[7:2] | 时值[15:8]

v     : 音高索引 = MIDI - base + 1（0 = 无音，上限 49）
base  : 左手 27（再整体 +12 半音）／右手 52
时值  : 单位 1/16 音符 = 250/3 ms
结束  : 表尾 (0,0)
```

> **为什么是 6bit 而不是 5bit**：5bit 只有 24 个值（2 个八度），而两手各自约 **4 个八度**
> ⇒ 必然大量折叠、旋律被压扁。`v0|v1<<6|v2<<12` 需 18 位超出 16 位 ⇒ 改用**跨字位打包**
> （4 声部 × 6bit + 8bit 时值 = 正好 32 位），既零折叠又不增加表长。

## 五、硬件接线

### 音频输出（核心）

| 引脚 | 复用 | 用途 |
|---|---|---|
| **GPIO4** | EPWM3A (CMPA) | **右手谱**（原音域 175~2637 Hz）|
| **GPIO5** | EPWM3B (CMPB) | **左手谱**（+12 半音，78~1245 Hz）|

- 两者经**三极管驱动**（如 SS8050，基极串 1 kΩ）或 **PAM8403 小功放**接喇叭
- **务必共地**；DSP 引脚只能出 mA 级电流，不能直接接喇叭
- **⚠️ GPIO4/GPIO5 同时是 LCD 的 DB2/DB3** ⇒ 沿用规则：**播放期间不写 LCD**

### 其它外设

| 外设 | 引脚 |
|---|---|
| LCD1602 | DB0..DB7 = GPIO2..9，RS = GPIO0，E = GPIO1，RW 接 GND |
| 板载 LED | D1..D5 = GPIO68/67/66/65/64，D6/D7 = GPIO10/11（低电平点亮）|
| 键盘 | 行 H1/H2/H3 = GPIO12/13/14（输入），列 L1/L2/L3 = GPIO48/49/50 |
| 数码管 | 74HC164：DSA = GPIO54，CLK = GPIO56；位选 GPIO70/71/72/73 |

## 六、关键设计说明与踩坑记录

### 1. `GpioCtrlRegs` 的 MUX/DIR/PUD 写入**必须用 `EALLOW`/`EDIS` 包住**
否则写入被**静默忽略**（不报错、不生效）⇒ 表现为引脚恒 0 V、**完全无声**。

### 2. ePWM 寄存器地址：**厂商结构体差 1 个字**
| 模块 | 基址 | **真 CMPA** | 真 CMPB |
|---|---|---|---|
| EPWM2 | 0x6840 | 0x6849 | 0x684A |
| **EPWM3** | **0x6880** | **0x6889** | **0x688A** |
| EPWM4 | 0x68C0 | 0x68C9 | 0x68CA |

- `&EPwm3Regs.CMPA` 会算成 `0x6888` ✗ ⇒ **必须用字面地址**
- **陷阱**：把 EPWM3 的 CMPA 写成 `0x6869` ⇒ 实际打到 **EPWM2** ⇒ 完全无声

### 3. PIE 中断归属
- **EPWM3_INT = INT3.3** ⇒ `PieVectTable.EPWM3_INT` + `PIEIER3.bit.INTx3` + `PIEACK.bit.ACK3` + `IER |= M_INT3`
- F2833x 的 `SysCtrlRegs` 部分偏移与手册不符 ⇒ 时钟寄存器用**字面地址**（如 `0x701E` / `0x7020`）

### 4. **本芯片 DMA 不能访问外设寄存器**
DMA 只能搬 RAM/外设数据寄存器，**不能写 CMPA** ⇒「DMA → CMPA」方案不可行，
故采用 **ePWM 周期中断喂 CMPA/CMPB** 的架构。

### 5. 载波频率的选择与负载类型有关
- **压电片（容性）**：电流 ∝ 频率 ⇒ **载波越高越响**（曾用 150 kHz）
- **动圈喇叭（感性）**：音圈电感性低通 ⇒ **载波低一些更厚**（现用 **25 kHz**）
- 约束：`载波 − 音频最高频 > 20 kHz`；载波 = 采样率 ⇒ 直接决定合成 CPU 开销
- `TBPRD = 150 MHz / 载波 − 1`（现值 **5999** ⇒ 25 kHz）；**改载波要同步改 `AUDIO_TICKS_PER_MS`**

### 6. 数码管使用「虚拟时钟」
`s_ms` 按**主循环轮数**累加（每 3 轮 +8）⇒ **循环越快计数越快**（这是刻意的设计手感）。
LED 在播放时改用「音乐最高音」决定步进速度，**与数码管彻底解耦**。

### 7. LCD1602 初始化时序必须放宽
初次初始化常常「没吃住」⇒ 表现为**上电偶发全黑**。
对策：① 延时放大 2~5 倍（上电 50 ms、复位间隔 10 ms/1 ms、E 宽 50 µs）；
② **开机 1.5 s 后再补做一次初始化并重画**（自愈）。

### 8. 增益链与数字余量（重要）
```
sine ±32767 → ×AUDIO_AMP_PEAK(3000) → 按声部数归一化(256/n)
→ ×每声部音高补偿(×1.0~×3.0) → ×3/4 → 软限幅(±2980) → duty = 3000 + m
```
- 可用占空比摆幅仅 **±3000**（中心 3000，上限 5997）
- ⇒ **数字峰值与补偿强度此消彼长**：补偿 ×3 时若要**零削顶**，`AUDIO_AMP_PEAK ≤ 1324`
- **响度应靠模拟端补**（供电电压 / 基极电阻 / 功放音量），而不是加大数字峰值

### 9. 已知物理现象（非缺陷）
播放时在 **GPIO6（LCD 的 DB4）** 可测到 25 kHz 耦合信号 —— 源于 GPIO4/GPIO5
陡边沿经相邻引脚/走线的**串扰**。播放中本就不写 LCD，**不影响显示与音质**。
若要抑制：走线分开，或在 DB4 线上串 100 Ω + 对地 100 pF。

## 七、已知限制

- **DD4（左手）低频受喇叭限制**：当前喇叭 F0 ≈ 700 Hz、600 Hz 以下陡降（−16~19 dB/oct），
  软件补偿只能改善，**无法彻底平衡** ⇒ 治本需换 **F0 ≤ 200 Hz** 的喇叭
- **播放期间不能刷新 LCD**（GPIO4/GPIO5 被音频占用）
- **`AUDIO_AMP_PEAK = 3000` + 补偿 ×3** 时低频重音仍可能有轻微削顶（最坏 6750 > 2980）
- 数码管计数速度依赖主循环耗时（设计如此）

## 九、OLED 显示与中文字幕

在 LCD1602 之外增加了 **0.96 吋 128×64 I2C OLED（SSD1306）**，两者并存、互不干扰。

### 9.1 硬件连接

| 信号 | 引脚 | 说明 |
|---|---|---|
| SCL | **GPIO15** | 软件（bit-bang）I2C 时钟 |
| SDA | **GPIO16** | 软件 I2C 数据 |

**不用硬件 I2C 模块**（免去 GPIO32/33 复用与 FIFO/中断配置）；速率约 100 kHz，
整屏 1024 字节刷新约 90 ms，因此**只在内容变化时刷屏**。

### 9.2 三块显示内容

| 时机 | 内容 | 函数 |
|---|---|---|
| 待机 / 按 K3 停止 | 信息界面：曲名、板名、按键号、计数、音乐状态 | `oled_show()` |
| 0 ~ 7.237 s | **旧 logo**：Develop by / Dr.ETO（83×43） | `draw_logo(0)` |
| 7.237 ~ 12.236 s | **新手绘 logo**：ふわふわ じかん（124×64，几乎铺满） | `draw_logo(1)` |
| 12.236 s 起 | **中文字幕**（跟随音乐，与歌声同源同步） | `oled_lyric()` |
| 音乐循环回开头 | 上述时间轴重新走一遍（歌词时钟对歌曲时长取模） | — |

### 9.3 歌词排版规则

```
每行 9 个字（14 px × 9 = 126 ≤ 128）
 ≤ 9 字   ⇒ 单行，水平 + 垂直居中
 > 9 字   ⇒ 折两行，优先在空格处断开，但必须保证两行都 ≤ 9 字；否则取中点
            上行 y = 16，下行 y = 34（32 px 内容块居中）
居中计算：忽略【行首空格】与【行尾空格】（空格本身也不绘制）
时钟：t_ms = (g_audio_samples / 25) % 歌曲时长(228686 ms)
      ⇒ 与音频采样同源，永不漂移，且每轮回绕后自动重新同步
```

### 9.4 字体与素材（全部生成物 → FLASH，零 RAM 占用）

| 文件 | 内容 | 生成脚本 |
|---|---|---|
| `MIDI/song_tables.h` | 双手曲表（6bit 跨字打包） | `build_tables.py` |
| `MIDI/font_tables.h` | 95 个 ASCII 8×8 + 198 个汉字 14×14（**按码点排序**） | `gen_fonts.py` |
| `MIDI/lrc_tables.h` | 39 行歌词时间戳 + UTF-8 文本 | `gen_lrc.py` |
| `MIDI/logo_tables.h` | 两张 logo 位图（SSD1306 页格式） | 位图转换 |

**⇒ `MIDI/` 是自包含的素材流水线**：只依赖 `MIDI/` 内的 `.mid` / `.lrc` / 图片，
所有脚本**只用相对路径**（`os.path.dirname(os.path.abspath(__file__))`）。

```bash
cd MIDI
python build_tables.py     # 曲表
python gen_lrc.py          # 歌词表
python gen_fonts.py        # 字库（复用 gen_lrc 的解析，保证与歌词表同源）
```

### 9.5 OLED 相关踩坑记录

| 问题 | 原因 | 解决 |
|---|---|---|
| 只显示一两个字 | 字库按"首次出现顺序"排列，却用**二分查找** | 生成时 `sort()` 按码点升序，并加校验 |
| 汉字段落整体缺字 | 歌词是"日文原句 + 〖中文翻译〗"，只取 `〖〗` 内容 | 生成脚本统一按 `〖〗` 提取 |
| 字形被裁一半 | Pillow 按"字符原点"定位，笔画超出 12×11 单元 | 改为**取墨迹包围盒后居中**，超限自动降字号 |
| 假名 9×8 不可读 | 假名转折多、浊点占 2 行 | 汉字用 14×14，必要时单独加大 |
| ASCII 看着像 5×5 | 8 px 字号下 cap height 只有 5 px | 改 10 px 并把基线放在第 7 行（留出下伸部分） |
| `meiryo.ttc` 打不开 | 该字体文件受系统保护 | 改用 `msgothic.ttc` / `YuGothR.ttc`；手绘体用 `Lolita.ttf` |
| 长句只显示一行 | 断行时无条件接受空格断点，下行超过 9 字被画出屏幕 | 断点必须满足"两行都 ≤ 9 字"，并加硬限幅 |
| 文本看着不居中 | 行首/行尾空格被计入居中宽度 | `visible_len()` 忽略行尾、`skip_lead()` 跳过行首 |
| 循环后歌词不同步 | `g_audio_samples` 只增不减，循环后 t_ms 远超最后一句 | 对歌曲时长取模（由曲表累加时值算得 228686 ms） |
| 表里有字却显示空白 | 字库脚本与歌词脚本各自解析 LRC，标点全角化后不一致 | `gen_fonts.py` 改为 `from gen_lrc import read_lyrics` |
